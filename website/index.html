Safe Sync

A five-stage safety pipeline

Promoting an object is never a raw EXEC. Base.It backs up the target, rewrites the CREATE to an ALTER, validates the T-SQL with ScriptDom, executes, then zips both sides for rollback. Every stage has to pass before the next runs.

FAQ

Questions, answered

What do I need to run Base.It?

Windows (it depends on DPAPI for credential storage and the git CLI for DACPAC staging) and network access to your SQL Server instances. It ships as a single self-contained executable — no .NET runtime install required on the target machine.

Will the drift watcher slow down production?

No. Every catalog read runs under READ UNCOMMITTED with a short lock timeout, and drift detection caps parallelism so the watcher never blocks your production SQL. It's designed to observe, not interfere.

Does the git integration commit or push for me?

Never. The git stager only creates a branch and stages files. Committing, pushing, and opening PRs stay entirely in your hands, so it fits any review workflow.

Where are my credentials stored?

Connection strings are encrypted with Windows DPAPI under the CurrentUser scope and live in your per-user app data folder — never beside the binary. Only the same Windows user on the same machine can decrypt them.

Subscription or perpetual — which should I pick?

Choose subscription if you want continuous feature updates and the lowest entry cost. Choose perpetual if you prefer to own the license outright; it includes one year of updates, after which a discounted maintenance renewal keeps you current.

Is there a free version?

Yes — the Free tier gives you unlimited Compare and the Query runner with one saved connection, forever. Upgrade to Pro when you need Sync, Batch, Watch, and DACPAC/git staging.
